# Skales — the plan

Working document for the rebuild. Decisions at the top, then the spec, then the order of work.
Everything in here is built from the existing generator (`tools/build.js` + `data/*`), so a new
page type is a data file and a template, never a hand-made page.

## SEO, GEO and schema

**Per page type** (generated, never hand-written):

| Page type | Title pattern (≤60) | Schema |
|---|---|---|
| Home | Websites & systems for service businesses \| Skales | Organization, WebSite, WebPage, VideoObject (the film) |
| Segment | Websites & booking for {segment} \| Skales | WebPage, FAQPage, ItemList (demos), Service |
| Service | {Service} for service businesses \| Skales | Service (in an OfferCatalog on the Organization), FAQPage, HowTo |
| Automation | {Automation}: how it works \| Skales | Service, FAQPage, HowTo |
| Case | {Build} — {segment} \| Skales | CreativeWork / SoftwareApplication, Breadcrumb |
| Compare | Skales vs {thing} \| Skales | WebPage, FAQPage |
| Note | {Title} | Article with dateModified, author Person |
| About | About Skales — one person, built in public | AboutPage, Person, ProfessionalService |

**Organization** becomes a `ProfessionalService` with a real `areaServed` region, `hasOfferCatalog`
listing the three services, `sameAs` for Instagram and any other profile, `logo`, `image`, `founder`.
No `aggregateRating` until there are real reviews.

**On every page:** canonical, one H1, an answer-first paragraph under it (the two sentences an AI
engine will quote), BreadcrumbList, OG card, description ≤160, self-hosted fonts preloaded, images
with width/height, lazy below the fold. Internal linking rules: every segment links its demos and
automations; every demo links its segment; every automation links the demos that include it.

**Build-time lint** (`tools/check.js`, runs inside `build.js`): refuses to ship a title over 60, a
description over 160 or missing, more than one H1, an image without alt, a broken internal link, an
OG image that does not exist, or an indexable page missing from the sitemap. Plus the browser pass
(`tools/qa.js`): every page at 1280 and 390, console clean, no overflow.

**GEO specifically:** `llms.txt` and `llms-full.txt` regenerated every build (exists), consistent
entity naming (Skales, Tom Griffiths, UK), the FAQ page as one clean source of answers, the segment
pages written to answer "what does a {segment} website need" in the first paragraph.

**Performance:** self-host Instrument Serif, Geist and Geist Mono as subset woff2; preload the two
above-the-fold files; defer the cold-open film until after first paint; keep the home page under 1MB.

## Design system

**Type.** Instrument Serif for display (editorial, expensive at size), Geist for body and interface,
Geist Mono for numbers. Self-hosted. Scale: 13 / 15 / 17 / 20 / 24 / 32 / 44 / 64 / 96, display
tracking −0.03em, body 1.5 line height.

**Colour.** Ink `#0E0E10`, Graphite `#141416`, Bone `#F6F3EC` (warm off-white instead of pure
white), Alu `#EDEBE6`, Hairline `#E2DFD8`, and the one accent the site borrows from whichever build
is running (existing `world()` maths). Accent appears only on the primary button, active states and
the k in the wordmark. Contrast: body ≥ 7:1, secondary ≥ 4.5:1, large ≥ 3:1, checked at build time.

**Motion.** Four moves, one curve `cubic-bezier(.2,.7,.2,1)`: reveal (12px + fade, 500ms, once),
crossfade (240ms), counter (800ms, tabular), lift (1px, 180ms). Cross-document View Transitions
between pages. Reduce Motion collapses every duration to 1ms; the cold open and the demos stay,
because they are content.

**Components.** Masthead, buttons (live / dark / ghost), device, wall tile, gallery card, panel with
sticky label, nameplate, FAQ details, CTA band, invite band, footer. Nothing new is added without a
place in this list.

**Imagery.** No stock anywhere. Drawn in code, or generated stills for the builder plates only.

**Voice.** Plain, confident, British. Short sentences. Says what it does, not what it is. No
"solutions", no "cutting-edge", no exclamation marks. Prices never. Proof only when real.

## The builder, version two (`/build/`)

**Why it reads as a template today:** one layout per trade, one photo, the name stamped into fixed
copy, the same structure every time.

**Inputs.** 1) what you do (segment chips in groups), 2) name and town, 3) direction: Quiet /
Direct / Loud (default chosen by segment, switchable after the build), 4) optional: drop in your own
photo, resized in the browser, never uploaded.

**Generated identity.** A logotype set in the direction's face, a mark derived from the initial
with a shape family per segment, a palette seeded from the segment hue and the name so no two
builds match, contrast solved by `world()`.

**Three directions, three real layouts.**
- *Quiet:* editorial. Serif headlines, whitespace, one photograph, numbered services, a three-step
  "how we work", one quote, plain footer, discreet call in the masthead.
- *Direct:* conversion. Photographic hero with the call, credentials band, services with "get a
  price", area ring, sample reviews strip, three-field form, sticky call bar.
- *Loud:* type as image, dark ground, a marquee of services, hard accent, duotone photograph,
  tap-to-call block.

**Behaviour modules, shared.** A working slot grid built from today's date; an estimator where the
segment quotes (figures marked as samples); an area ring drawn in SVG around the town; a services
grid; a four-question FAQ; the sticky call bar; a form that confirms in place.

**Copy bank per segment.** Three headlines, three subs, six services each with two descriptions,
three credential sets, four FAQs, two quotes labelled as samples, the CTA verb. Seeded by
name + town, so the same inputs always give the same site.

**Shareable.** The build lives in the URL (`/build/#s=roofing&n=…&t=…&d=direct`), so a link in a
DM regenerates it. "Send me this" opens `/book/` with those details filled in.

**Choreography.** Identity first (the logotype draws), then the hero, then the sections at 180ms
steps; about three seconds; the timer stays. With Reduce Motion it appears at once.

**Quality gate.** A test generates 60 random builds across every segment and direction and checks
each at 390px for overflow and contrast. A build that fails does not ship.

**Plates.** Three crops per segment, generated, no stock. About 75 images.

## Contact

WhatsApp first on a phone, then the form, then email. The form posts to a real endpoint (Formspree
or a small Cloudflare Worker) with the WhatsApp/mailto hand-off kept as the fallback. Calendly
embedded on `/book/` the moment the link is in `data/site.js`.

## Measurement

Search Console and Bing Webmaster on launch. Privacy-light analytics (Plausible, or Cloudflare Web
Analytics free) with four events: builder started, builder built, builder sent, call booked.

## Order of work

1. **Now:** buy the domains; merge the current branch (the 404 fix affects the live site).
2. **Foundation:** design system (tokens, fonts, motion), the new shell, the URL scheme with every
   redirect, home / work / build split. Done when the three pages ship in the new system and the
   full QA passes.
3. **Builder v2.** Done when the 60-build quality gate passes and three directions ship for every
   segment.
4. **Page factory:** segments, services, automations, lanes, compare, FAQ, about, location. Schema
   upgrade. `tools/check.js` in the build. Done when ~100 pages pass lint and the browser pass.
5. **Launch:** flip the origin, rebuild, re-lock demos, re-render OG, set DNS, Search Console,
   analytics, and a final full QA on the live domain.
6. **After:** one note a week, one build a week, segments added as demos land.
